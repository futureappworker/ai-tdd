# SOP

## Phase 1: 確認測試接縫

1. Read 讀取使用者需求與即將修改的程式，取得要建立或修正的行為。
2. Read 讀取存在的 `GLOSSARY.md` 與修改範圍內的 ADR，取得領域詞彙與既有決策。
3. Read [測試接縫規範](rules/測試接縫規範.md)並取得接縫確認要求。
4. Think 依已載入規範提出每條候選接縫的公開介面、抓到的行為與漏掉的行為，並在使用者確認前停止。

## Phase 2: 撰寫失敗測試

1. Read [測試品質規範](rules/測試品質規範.md)並取得公開行為、反模式、3A 註解分段與系統邊界的判斷要求。
2. Think 依已載入規範決定本輪要覆蓋的一條已確認接縫、該測試要觀察的公開行為，以及該接縫是否跨越系統邊界。
3. Read 本輪接縫跨越系統邊界時，讀取 [邊界模擬規範](rules/邊界模擬規範.md)並取得邊界依賴的模擬要求。
4. Think 依已載入規範決定本輪測試要替換的外部依賴。
5. Read [紅燈綠燈循環規範](rules/紅燈綠燈循環規範.md)並取得單輪失敗測試的範圍要求。
6. Write 依已載入規範將本輪這一條測試寫入本輪接縫對應的測試檔。

## Phase 3: 檢查失敗測試

1. Read 依已載入規範檢查本輪測試檔與本輪測試的執行輸出，並列出不符合項目。

## Phase 4: 修正失敗測試

1. Write 依已載入規範修正本輪測試檔的全部不符合項目。

## Phase 5: 實作最小通過

1. Write 依已載入規範修改本輪接縫的實作檔，使本輪測試通過。

## Phase 6: 檢查實作

1. Read 依已載入規範檢查本輪實作檔與本輪測試的執行輸出，並列出不符合項目。

## Phase 7: 修正實作

1. Write 依已載入規範修正檢查所列不符合項目所在的本輪實作檔或本輪測試檔。

## Phase 8: 決定是否重構本輪

1. Read [重構循環規範](rules/重構循環規範.md)並取得重構範圍與禁止事項。
2. Think 依已載入規範列出本輪可做的結構改善，或得出本輪跳過重構；若跳過重構，跳至 Phase 12。

## Phase 9: 執行重構

1. Write 依已載入規範只修改本輪觸及的實作檔，不改公開行為、不新增測試。

## Phase 10: 檢查重構

1. Read 依已載入規範執行專案測試指令，檢查本輪相關測試與既有測試的執行輸出，並列出不符合項目。

## Phase 11: 修正重構

1. Write 依已載入規範修正 Phase 10 所列不符合項目所在的本輪實作檔或本輪測試檔。

## Phase 12: 決定下一輪

1. Think 判斷已確認接縫是否都已有對應測試；若仍有未覆蓋接縫，從 Phase 2 再執行一輪。
